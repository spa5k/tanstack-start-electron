Production

Two ways to host the same fetch handler.

Custom scheme · default

In-process handler. No TCP port.

Electron renderer app://renderer/
▼protocol.handle
Electron main imports .output/server/index.mjs and answers every request
0 listening sockets

Loopback HTTP · optional

Child process. Normal web behavior.

Electron renderer http://127.0.0.1:<random>
▼fetch
Child process srvx serves the same handler with normal cookies
1 loopback socket

Proof

No process listens on TCP.

Terminal — scheme mode
$ lsof -a -p "$(pgrep -f 'Contents/MacOS/Electron' | tr '\n' ',' | sed 's/,$//')" \ -iTCP -sTCP:LISTEN -P -n (no output) $ # the app is still running and serving SSR, RSC and server functions
